# 重复索引隔离排查

## 现象和已验证路径

现有 FAISS 和 BM25 索引都曾测得 3,596 条记录、2,336 个不同 `(paper_id, chunk_idx)` 键。历史重复的实际来源尚未确认。

在仅包含一个合成论文块的系统临时目录中，`.venv\Scripts\python.exe -B -m evaluation.reproduce_ingestion_retry` 调用真实入库编排及真实 FAISS/BM25 持久化，但用合成向量和合成论文替代模型和网络：

```text
INTERRUPTED simulated interruption before history write
AFTER_FAILURE 1 1 HISTORY False
AFTER_RETRY 2 2 UNIQUE 1 HISTORY synthetic-1
```

这证明一种可行故障路径：索引已经写入，历史记录尚未写入时发生中断，之后按缺失的历史记录重试会重复追加。复现注入点是历史记录写入前的模拟异常，并非真实断电；不能据此认定现存重复一定由此路径产生。临时目录由脚本自动清理，不读写用户真实索引、PDF 或导入历史。

## 代码证据

- `application/ingestion.py` 先逐篇调用 `add_chunks`，循环结束后才记录成功论文 ID。
- `infrastructure/indexes.py` 分别保存 FAISS/元数据和 BM25，当前没有覆盖全部文件及历史清单的共同事务。
- `infrastructure/arxiv.py` 按 `ingested.txt` 判断已导入论文；缺失记录时可能再次获取同一论文。
- 检索结果和 RRF 去重可减少重复候选的影响，但不修复磁盘中的重复记录或 BM25 语料统计。

## 候选治理方案，尚未实施

1. 先只读核查 FAISS 向量数、元数据顺序、BM25 文档与词项、论文和块 ID 的唯一性及文本对应关系；任何不一致应明确报错，不应自动丢弃或覆盖数据。
2. 在独立目录从明确记录的输入及模型版本构建一个完整新版本；记录文本及索引文件指纹、模型配置、映射清单。仅验证条数和文本哈希不足以证明向量确由对应文本及模型生成。
3. 保留完整旧版本，通过单一版本标识或指针进行受控切换；明确 Windows 同卷、文件占用、并发读写、进程崩溃与恢复语义。逐个替换多个索引文件并不能提供跨文件原子性。
4. 在临时测试库注入以下失败：写 FAISS 后中断、写 BM25 后中断、记录历史前中断、并发导入及版本切换中断。每次检查重启后的可读性、无静默覆盖和是否可回到先前版本。
5. 在副本中验证去重策略及新旧结果差异，再确定是否迁移正式资料库；已存在的 PDF、用户数据和会话数据库需独立保护。

## 本轮不做的事

本轮没有直接删除重复记录、重建或覆盖现有索引，也没有将会话 SQLite 视为论文入库事务的一部分。生产迁移需要完整实现、隔离测试与可用恢复点。
